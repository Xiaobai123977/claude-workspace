### 上下文、缓存与 Token 统计（2026-10-16）

输入框下方新增用量入口，展开显示上下文占用、最近回答和当前分支的输入/输出/缓存读取/缓存写入明细。`/usage` 使用同一套统计。分支合计包含继承历史；缓存命中率按缓存读取占总输入的比例计算，跨回答采用加权比例。上游没有返回缓存信息时显示“未报告”，明确返回零时才显示 0%。

Anthropic 输入与缓存计数保留原语义；Chat/Responses 的含缓存输入计数先拆分再转换，防止缓存重复计算。代理读取用量时保持原生 Anthropic 转发字节不变。流式快照按 API 消息 ID 去重，工具循环按不同请求求和；最终 CLI result 作为该回答的汇总。共享历史从原生消息重建请求用量，GUI 元数据保存最终汇总与缓存报告状态。

上下文占用、容量和百分比只采用 CLI 上下文报告，移除最近请求 Token、result 模型容量和供应商声明窗口的估算回退。未读取、消息变化或模型/接入/推理强度改变使报告失效时，显示“待读取”，不显示旧值或估算值。已连接且空闲时可手动读取 `get_context_usage`，采用 CLI 的 totalTokens/maxTokens 与分类；不累加分类中的空闲空间、预留和延迟加载项目。手动报告绑定当前消息、接入与原生会话。默认统计仅通过本地 IPC 读取已有数据，不额外调用模型；原生刷新由用户手动触发。
