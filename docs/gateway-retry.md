# 网关重试与等待边界

## OpenAI Chat 工具历史兼容

Chat 要求 assistant 的 `tool_calls` 后紧接对应的全部 tool 结果。Claude 原生消息允许文字和 `tool_result` 放在一起，直接按文字优先转换会打断这个顺序，造成反复 400；中断留下的缺失结果也会触发同类错误。

网关仅在发往 Chat 上游的请求中整理这些记录：先放齐当前工具调用的真实结果，再放后续文字和图片；缺失结果明确标为不可用、执行状态未知，提示核实当前状态后再重试操作。不会为填补历史执行工具，不修改原生 JSONL，不跨后续 assistant 回合借用结果。孤立或重复结果作为注明来源的历史数据保留。已完整且顺序合法的历史保持不变，避免影响正常的缓存前缀。Anthropic 与 Responses 协议不应用此整理。

## 调用失败后的额外重试

在原有网关重试、线路切换和 Claude CLI 处理结束后，整次调用仍以错误结束时，额外自动重试 3 次，每次固定等待 3 秒。不区分 HTTP 错误类型，也适用于 CLI 异常退出和未返回完整结果。第三次额外尝试仍失败才展示最终错误。此预算独立于下面的原有网关策略，每次额外尝试仍使用原策略。

等待时显示原始错误摘要和“额外重试 1/3”。沿用原聊天及原生会话，保持输入和附件引用，不创建分支；CLI 可能将重新发送的输入追加到同一份原生历史。已完成的文件操作不会自动回滚。点击停止会取消倒计时和调用，不自动重试用户主动停止的任务。

自定义供应商请求默认最多重试 10 次（初次请求不计入重试）。线路超过 11 条时，预算至少覆盖每条兼容线路一次。可重试 HTTP 408/409/425/429/5xx、瞬时网络错误、每次尝试的超时。400/401/403/404/422 不直接重复同一错误，但可尝试尚未访问的兼容备用 Key/供应商。单次请求优先遍历未尝试的健康线路，避免粘性路由或高权重反复选回失败线路。

尊重同一上游的 Retry-After 和 x-should-retry:false；独立的兼容备用线路仍可切换。超过等待上限不提前重试。401 的 Key 暂停 30 秒，403/404 的模型线路暂停 3 秒，不再无限期停用；已确认成功的生成响应清除该线路旧的健康错误。权限确实不足时仍会如实失败，不修改配置或假装调用成功。

`/messages/count_tokens` 属于辅助计数接口：只选择支持原生计数协议的线路，不改变生成会话的粘性选择；其 404、超时等失败不会污染生成线路的健康状态。没有计数端点不等于模型不能生成。

## 错误来自哪里

返回错误保留上游原文（凭据脱敏），并携带 `source`：`upstream_http` 表示上游实际 HTTP 错误；`upstream_body` 表示 HTTP 200 中的错误正文；`local_router` 表示本地路由拒绝。`upstream_status` 记录实际 HTTP 状态，正文中的显式状态另记为 `reported_status`，本地状态另记为 `routing_status`。内部用于调度的 503/529 不当作上游真实 HTTP 状态。

本地路由失败、HTTP 200 错误正文及最终的上游 401/403/404 对 CLI 返回网关错误 502，同时保留上述来源和原始信息，避免 CLI 将上游线路 404 改写成“所选模型不存在”。实际上游 HTTP 503 仍保留 503。本地冷却等待显示“本地线路冷却或路由不可用”。

## HTTP 成功不等于模型已开始输出

代理在返回给 CLI 前，检查流的初始阶段。HTTP 200 中的错误事件、JSON 错误封套、首次有效输出前的断连/空响应/无效 JSON，都进入相同的有界重试。只发 ping/注释、role 或 response.created 等元数据不等于有效模型输出，仍受单次超时约束。错误类型用于内部判断，不把推算出的 HTTP 状态冒充真实上游 HTTP 状态；显示实际错误类型和上游原文，敏感凭据脱敏。

首个可交付的内容/思考/工具事件之后，响应直接流向 CLI，不整段重放，避免重复文字或工具执行。后续流错误如实显示，上游健康状态用于后续请求的线路选择。静默失败或容量不足不能被描述为成功。

## 防止等待卡住

- 读取错误正文的提示最多等待 1 秒；不因错误正文一直不结束而占满整个请求超时。
- 丢弃失败响应不阻塞下一次重试，同时中止旧尝试，清理计时器和取消监听。
- 线路冷却包含在下一次等待中，不把仅仅等冷却的本地拒绝消耗成额外上游尝试。
- Anthropic 转发遭遇背压时，同时监听 drain、close、error 和取消，避免连接已关闭还无限等 drain。
- 停止操作取消当前请求和重试倒计时；不为用户主动取消标记坏线路。

默认持续等待响应，不设请求总时限；旧连接未明确配置等待方式且使用旧默认 120 秒的，按持续等待处理，其他自定义时长继续保留。高级连接设置可关闭“持续等待响应”并指定 10–3600 秒；模型详情的超时留空继承连接，0 为持续等待。明确设置的时限仍是单次请求总时限。持续等待不等于隐藏真实错误：对端关闭、网络失败和实际错误正文仍进入原有重试流程。

上游 HTTP 传输使用 Node HTTP/HTTPS 的流，没有 fetch 隐式的响应头/响应体等待期限；支持 gzip/deflate/br 解码、明确 Content-Length 和 AbortSignal 取消。连接建立仍受操作系统及对端行为限制，不承诺断网后连接永远存在。

首次请求等待 10 秒后显示“等待上游有效响应”和已等待秒数；只有显式设置超时才显示截止时间。新尝试开始后显示当前等待状态，不继承上次的 HTTP/冷却错误。真实线路冷却在选路阶段等待，不伪造 HTTP 错误，也不消耗上游重试次数；开始请求后清除冷却提示。本地设置的超时不会使 Key 进入健康冷却。停止操作仍立即取消等待或网络请求。

首次有效响应通过检查后立即取消“等待有效响应”的提示定时器，流继续输出时不会重新弹回等待状态；单次请求超时和取消机制继续生效。外层额外重试的提示也会在主模型开始输出文字、思考或工具调用时清除，不清除其他独立请求仍在等待的状态。

## 验证

单测覆盖三种协议初始流错误、HTTP200 JSON 错误、心跳超时、初始 body socket 错误、无效/空响应、保留错误原文、密钥脱敏、停止、响应取消挂起、背压关闭、单 Key 冷却和多 Key 切换。已交付的文字/工具调用断流不重放。

`npm run test:gateway-retry-ui` 使用真实安装的 Claude CLI 和本地上游，不调用付费供应商；验证 429/503、流内过载、心跳等待的超时/恢复、取消、聊天隔离及十次上限。CLI 的独立输入建议请求由测试上游单独响应，不混入主请求的重试计数。测试不会修改真实供应商配置。

`npm run test:final-error-retry-ui` 使用测试 CLI 验证外层三次预算、三秒间隔、中途恢复、CLI 异常退出、停止取消和原聊天复用。网关界面回归同时验证每轮原有 11 次请求（初次加 10 次重试），四轮合计 44 次；原有单元测试保持原策略的断言。

`npm run test:gateway-failover-real-cli` 使用已安装 CLI 复现“上游 404 → 模型不可用”提示，验证网关保留错误原文、同一保存配置恢复、备用 Key 接管。模拟测试另外覆盖计数 404 不污染生成、14 种状态的备用线路切换、13 个 Key 遍历、暂停过期恢复及错误来源区分。测试均使用隔离目录和虚构上游，不代表已经实测用户所有真实供应商。

`node scripts/gateway-long-wait-test.cjs` 用真实本地 HTTP 连接并发等待 125 秒：一路迟迟不返回响应头，另一路先输出再等待。验证旧 120 秒默认配置迁移后，两路都只有一次上游请求、完整返回，无提前断连、健康冷却或重试。`tests/upstream-wait.test.cjs` 另覆盖持续等待/显式时限、旧配置迁移、gzip、取消、冷却不消耗预算以及新请求不沿用旧原因；网关界面回归验证持续等待无超时倒计时且可停止。
