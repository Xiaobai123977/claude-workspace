# 代码变更与原生文件恢复

2026-10-16。主要入口是回复下的“本轮文件变更”卡片及聊天顶部“代码变更”。界面不以每条消息的恢复点列表代替文件审阅。

- 有实际改动的轮次才显示文件数、增删行数和文件路径。点开默认显示该轮固定预览。
- 右侧连续排列文件，默认左右对照，可切单列、按路径筛选、逐文件或全部折叠。
- “工作目录全部变更”显示当前项目全部未提交修改，包含本轮开始前已有的改动；其余选项是已记录的轮次。
- 没有 AI 审查按钮或重复的会话分支按钮。审查使用 `/code-review`，分支/重新生成在消息旁操作。
- 工具栏历史图标打开“恢复文件”。用户选一个消息前的原生恢复点，仅有一组恢复操作；恢复前确认覆盖范围，聊天保留。此操作仍由 CLI `--rewind-files` 完成，不宣称能撤销 Git、Shell 或远端副作用。

## 数据范围

Git 项目在轮次开始时记录 HEAD 标识和原有脏文件基线，结束后计算净变化；没有创建提交，没有改写用户 Git 索引。覆盖工作目录可见的 Git 修改，包括 Shell 产生的修改。项目执行期间发生的外部编辑也可能落在此时间范围内，不能据此证明全部由模型创建。

非 Git 项目在原生 Write/Edit/MultiEdit/NotebookEdit 执行前记录目标文件，结束后比较。此范围不包括无法识别路径的 Shell 写入；界面明确标注“按 Claude 原生文件编辑工具记录”。子代理的同类工具事件也参与记录。

这里只缓存实际变更的文本差异，不为每次聊天复制整份项目。旧版本聊天没有准确的轮次基线，不反推或伪造历史本轮差异，仍可查看当前工作目录及使用 CLI 原生恢复点。

单文件文本预览上限 1 MB、每轮最多 200 个候选文件、内容总预算 16 MB；二进制及超过限制的已知改动只记录路径并说明原因。固定预览不会随下一轮修改或文件恢复而变化。差异缓存在应用数据 changes 目录，正文仍由 CLI 历史管理；轮次摘要随消息元数据保留。分支复用相同轮次的预览，删除聊天时清理不再被其他聊天引用的预览，不删除项目文件。

## 验证

单元测试覆盖已有脏文件排除、Shell 新建/删除、空文件、非 Git 编辑、子代理编辑、失败工具、中文路径、子目录及二进制限制。隔离 Electron 测试覆盖两轮编辑、旧预览固定、工作目录切换、筛选/折叠、恢复确认取消、重启及删除缓存。真实安装的 CLI 与本地模拟上游验证 Read/Write、变更卡片、原生历史同步、检查点分支与文件恢复，没有调用用户上游。
