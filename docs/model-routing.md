# 多供应商与多 Key 路由

入口：设置 → 连接与模型 → 自定义 API。

## 配置顺序

1. 在「供应商与 Key」添加供应商，填写 URL、协议和 Key，设置供应商权重。
2. 一个供应商可以添加多个 Key。每个 Key 分别设置名称、权重、启用状态，并独立获取自己的模型目录；可以分别重新检测。
3. 供应商模型列表是各 Key 目录的并集，用于勾选聊天中显示的模型。编辑模型能力时先选择归属 Key；某个 Key 的思考档位不会被复制给其他 Key。
4. 直接启用供应商，即可在该供应商的匹配 Key 之间轮转。需要跨供应商时，进入「模型服务池」。
5. 模型覆盖表按完全相同的模型 ID 汇总供应商和 Key 数量，区分接口检测结果与手动声明。点击「创建模型池」可填入同 ID 的供应商；统计来自已保存目录，刷新统计不会重新请求上游。
6. 模型池填写一个对外模型 ID，再为各供应商选择上游模型 ID。不同 ID 可以映射到同一个对外模型。展开「参与的 Key」可限定线路；同一供应商可以添加多行，为不同 Key 映射不同上游 ID。同一 Key 在一个池中只能映射一次。
7. 保存并启用模型池后，当前聊天与后续新聊天使用此模型池。聊天模型菜单显示池的统一模型，不混入其他连接或订阅模型。

## 权重与粘性

采用两层平滑加权轮询：先选择供应商，再选择该供应商内的 Key。权重范围均为 1–1000。A/B 供应商权重为 1/3 时，无粘性的长期分配约为 25%/75%；给 A 增加更多 Key 不会提高 A 的供应商份额。

默认启用粘性：同一聊天、同一连接与模型优先使用原供应商和 Key，默认有效期为 60 分钟，每次命中续期，可设置 1–10080 分钟。权重主要分配新聊天及需要重新选路的请求。关闭粘性后逐请求轮询，CLI 的建议生成等辅助请求也参与轮询。

粘性关系独立保存，重开应用仍有效；只记录经过散列的聊天关联标识、线路 ID 与过期时间，不保存 Key。供应商凭证继续使用系统加密保存，旧版单 Key 供应商可直接读取，只有显式保存时才转换配置结构。

## 可用线路与故障切换

- 只使用启用的供应商、Key 与模型，排除上次目录检测中已消失的模型。每个 Key 必须有自己的模型记录；允许在高级设置中为指定 Key 手动声明模型和能力，手动声明不等于接口检测成功。
- 指定思考档位时，仅选择该 Key 的模型能力明确支持此档位的线路。图片和工具请求也会排除明确声明不支持对应能力的线路；未知能力不被假装标为已支持。
- 429、503 等临时故障会使失败 Key 进入冷却。有其他兼容线路时立即切换；全部冷却时按上游等待要求重试。沿用最多 10 次自动重试与停止按钮，不因换线增加无限重试。
- 401 暂停该 Key；403/404 只暂停对应模型线路，保留同一 Key 的其他模型。暂停后仍返回原始上游状态和经过识别的原因，不伪装为新的 503。重新保存供应商配置或重启应用会重置这些内存中的故障状态。粘性失效或原线路停用时重新选择；故障切换后的线路成为新的粘性目标。
- 只有收到成功响应头之前才自动重试或切换。已经开始输出的流不会重新播放，避免重复文本或工具执行。
- 聊天消息旁显示实际供应商和 Key 名称；悬停可查看实际模型 ID。等待提示保留错误码、重试次数和失败线路名称，不显示凭证或上游原始错误内容。

## 协议边界

支持 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 混合组池。每次选路重新转换请求和上游模型 ID；URL、认证和能力均来自选中的供应商与 Key。

切换线路或重新建立代理连接时，不转发无法确认归属的历史 thinking/redacted_thinking 块，避免跨账号复用签名或不透明推理数据；普通文本与工具历史继续保留。由当前 Responses 线路返回的不透明推理数据带有线路归属，并且只允许原线路重放。不同模型的原生私有推理状态无法保证连续。

OpenAI 协议不提供 Anthropic 原生 token 计数；混合池的原生计数取决于选中的线路。不保证不同上游的工具行为、上下文长度和语义完全一致，手动映射需自行确认模型可替代。

## 验证

`npm test` 包含两层权重精确比例、每 Key 目录和凭证隔离、检测失败保留原目录、思考能力过滤、跨协议别名切换、同供应商不同 Key 别名、重复映射拒绝、重启粘性及旧配置兼容测试。

`npm run test:model-routing-ui` 使用真实 Electron 和本机 Claude CLI，但只访问本地模拟上游；验证界面创建、独立检测、加密持久化、模型池启用、429 换线、实际线路显示和关闭重开后的粘性。测试识别 CLI 的辅助建议请求，并检查它们也遵守粘性。所有配置均在独立临时目录，不读取用户凭证或调用付费模型。

模型池会以容量已声明的兼容线路的最小上下文/输出上限限制 CLI；存在已知上下文时排除未知容量线路，避免故障切换突破声明窗口。模型级协议参数、显式验证和备份见 [模型档案](model-profiles.md)。
