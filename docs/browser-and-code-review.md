# 内置浏览器与代码变更

## 使用

聊天顶部的地球按钮打开内置浏览器；文件图标打开代码变更，两者位于聊天旁边。

先启动项目自己的开发服务器，在浏览器地址栏输入 `http://localhost:端口`，也可以打开普通 HTTP/HTTPS 网站。提供后退、前进、刷新、截图加入聊天和系统浏览器打开功能。

「选中修改」进入元素选择模式，移动鼠标高亮，点击选择，Esc 取消。填写修改要求后，点击「将元素与修改要求加入聊天」。聊天草稿包含简短的修改要求、元素标签和页面截图；选择器、位置、HTML 提示与样式作为结构化上下文随消息交给 CLI。消息发出后也可展开查看选中快照。发送前会检查文档、选择器、标签和文字是否仍匹配；页面刷新或元素变化后，需要重新选择。

「Claude 可操作」是当前聊天的开关，默认关闭。开启后，下一次发送时通过临时 MCP 配置加载内置浏览器工具，不修改用户 `.claude` 或 `.mcp.json`。可用工具包括打开网页、读取页面、点击、输入、按键、滚动、截图、后退、刷新，以及控制台与失败请求检查。它们使用和手动预览相同的页面。正常权限模式仍沿用 CLI 的工具审批与规则；安全模式停用这些工具。关闭开关会撤销旧的浏览器访问令牌。

代码变更区分固定的“本轮变更”和“工作目录全部变更”，回复下提供实际改动的文件摘要。右侧连续审阅文件，支持筛选、折叠、增删统计、行号和单列/左右对照。工作目录范围依赖 Git，包含暂存、未暂存和新增文件，运行中、结束及重新获得焦点时刷新；本轮预览不随之后的修改改变。原生文件恢复收进次级入口，隔离工作区仍由项目右键管理。详见 [变更审阅](changes-review.md)。

## 范围

- 页面运行在独立的 WebContentsView 和每聊天独立的内存浏览器会话中。启用沙箱和上下文隔离，不向网页提供 Node、应用 preload 或应用 IPC。
- 浏览器不读取系统 Chrome 登录状态；关闭应用后浏览器 Cookie 和打开的页面不保留。相同聊天在应用内切换面板时保留页面。
- 支持 HTTP/HTTPS，以及当前聊天项目内的 file:/// HTML 链接。后者通过每聊天独立的本地预览服务打开，支持相对资源、模块脚本和页面跳转，拒绝项目外文件和隐藏路径。下载、摄像头等网页权限不自动放行；需要下载时在系统浏览器中处理。
- 元素选择和当前工具检查针对主文档，尚不穿透跨域 iframe 或 Shadow DOM。截图为当前视口，最大宽度 1280px。
- 任意第三方网页无法保证对应本地源码。元素信息用于让 Claude 在项目中查找组件，并非可靠的源码定位。代码修改使用原生文件工具；不会把临时 DOM 改动伪装成源码保存。修改质量仍取决于当前模型和项目。
- 当前提供元素批注修改流程，没有完整的可视化拖拽编辑器、设计系统管理或设计稿导入功能。
- 二进制、大型内容和大量新增文件受预览限制；不是完整 IDE 或 Git 提交管理器。

## 实现与验证

浏览器会话通过受随机令牌保护的 loopback 服务连接到轻量 stdio MCP 桥。临时配置不进入前端状态，应用退出删除，重启时清理本应用遗留的桥配置。浏览器各聊天之间不共享页面和认证令牌；顶层应用 IPC 只接受主界面主 frame 的请求。

`npm run test:browser-ui` 使用真实 Electron，验证两种差异视图、中文文件名、网页隔离、实际 MCP 桥调用、DOM 选择、失效快照拒绝、截图与结构化上下文进入草稿、发送后的消息保存以及关闭控制开关后的访问拒绝。

`npm run test:browser-real-cli` 使用本机真实 Claude CLI、真实 MCP stdio 子进程和本地模拟模型上游。测试从实际点选元素开始，验证定位信息与截图进入 CLI 请求，随后执行浏览器导航、检查、输入、点击、截图和诊断，使用原生 Read/Edit 修改测试 HTML，刷新并再次检查新文字，最后验证代码差异。上游返回预设工具调用，验证接入链路，不评价真实模型自主设计能力；不调用付费模型。

元素批注的数据组织参考 [OpenDesign 源码调查](opendesign-source-research.md)。浏览器使用 [Electron WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)，动态工具接入使用 Claude CLI 的 [`--mcp-config`](https://code.claude.com/docs/en/cli-reference)。

## 聊天链接与当前页面上下文

聊天 Markdown 中的 HTTP / HTTPS 链接直接打开当前聊天的内置浏览器；面板已打开时也会导航到新链接。地址栏支持手动导航，“在系统浏览器中打开”仍为独立操作，失败会显示错误。

内置浏览器显示是否连接到 Claude。开启“Claude 可操作”后，下一条消息附带浏览器当前 URL、标题、加载状态和错误信息，提示使用 workspace_browser 的 inspect / screenshot 等工具读取页面；这些状态按不可信网页数据处理。未开启或处于安全模式时不注入页面状态、不提供浏览器控制桥。打开链接本身不会自动授予模型操作权限；截图仍由用户显式附加或由模型调用截图工具获取。

浏览器 UI 测试覆盖直接点击聊天链接打开面板、面板内继续导航，以及检查、点击、输入、截图和撤销权限。三种协议的真实 CLI 测试额外确认上游收到当前浏览器上下文；使用本地预设上游响应，不验证具体供应商模型的理解能力。

本地 HTML 链接点击、中文/空格路径、CSS、模块脚本和相对跳转已纳入 Electron UI 测试。真实 CLI 浏览器流程也可使用 `CLAUDE_GUI_TEST_LOCAL_HTML=1` 验证本地页面的检查、截图、源码编辑和刷新。

## 附件发送方式（2026-10-16 更新）

聊天和元素批注保留图片预览，但附件只以本地文件路径传给 CLI。浏览器 MCP 截图同样返回本地文件路径，不主动注入图片块。模型按需调用文件工具；若文本模型的工具结果或旧历史仍混入图片，网关会转为文件引用，保证后续文字和源码操作可以继续。此项取代此前直接把截图图片块送入模型的默认行为。
