# 子代理完成与主模型汇总

子代理返回只表示子任务结束。一次开发/拓扑任务还可能需要主模型读取结果、去重、核对连接、写入文件与验证。界面不能把“全部代理已返回”当作主任务完成。

## 完成协议

`run-lifecycle.cjs` 维护当前主任务的新结果和原生会话状态：

- 子代理带 `parent_tool_use_id`、`parentToolUseID` 或 sidechain 标记的结果，不是主任务的 result。
- 主模型可能先返回一条结果并进入 idle，同时仍有后台任务。这一组 result/idle 不能在最后一个 task notification 到达时被重复用于结束汇总阶段。
- 子代理自然完成、新一轮主模型流、主工具调用和权限请求会失效旧的终态；等待主模型本轮的新 result 和 idle。旧版 CLI 没有状态事件时仍保留短暂尾流宽限，但计时器触发前重新校验结果、任务和权限状态。
- 同一结果之后、idle 之前迟到的纯文本规范化快照仍保留；新工具调用不属于这种尾流。
- 明确取消子任务的确认，以及主任务已有明确错误的场景，不能无限等待一个不会到来的成功汇总。旧轮任务的迟到通知不影响新轮。
- 后续原生权限请求或新流启动不能因为上一段曾结束而直接拒绝；自然继续仍沿用正常权限控制。

停止当前任务仍使用原生 interrupt，不会靠额外模型请求自动续跑。现有连接与原生会话历史保留，不重复派出已完成代理。

## 阶段展示

聊天显示代理返回数量、当前阶段和经过时间：探索 → 等待主模型核对汇总 → 写入。拓扑任务明确显示“等待主模型核对并汇总写图 / 尚未完成主任务”。这些提示反映本地观察到的执行阶段，不证明上游正常，也不把等待时间描述为额度错误。

探索指令优先要求同批前台并行 Agent/Task 调用，等待真实工具结果后统一合并。如果确需后台代理，主模型应使用可用的等待/结果工具收齐结果，不能仅回复“继续等待”就结束主任务。写图并验证成功（或有依据地确认无需变更）才报告完成。

## 验证

`tests/run-lifecycle.test.cjs` 覆盖旧终态失效、子链结果隔离、宽限计时器、规范化尾流、取消与错误确认、汇总阶段计时。

`npm run test:agent-merge-ui` 重现“先返回旧 result/idle、最后一个子代理完成、主模型延迟请求 Write 授权”的顺序，验证整个过程仍在原回复中运行、拒绝覆盖中的新输入，并最终完成授权写入。测试使用独立临时配置与本地 CLI fixture，不调用真实供应商。
