# Claude 输入与命令交互

2026-10-16。取代把应用页面导航混入 `/` 的旧交互。

## 输入框

| 输入或操作 | 当前行为 |
| --- | --- |
| `/` | 从实际安装的 CLI 的 initialize 响应读取 commands；不发用户消息，不调用模型。默认仅列常用入口：代码审查、简化、安全审查、初始化、启动验证、目标、循环、压缩上下文、清空上下文（以当前可用能力为准） |
| `/goal 完成条件`、`/goal`、`/goal clear` | 原生 CLI 设置目标、查看状态、清除目标；不另建 GUI 目标管理面板。命令仅填入输入框，发送后执行 |
| `/loop 间隔 提示` | 原生会话循环。跨重启保留的本应用计划仍在“计划任务”页面 |
| `/名称` 或 `/中文用途` | 搜索其余已发现命令及 GUI 快捷入口。模型、权限、设置、MCP 等已有界面的功能不再重复铺在默认列表 |
| 选择技能 / Tab | 填入 `/名称 `，可补充目标或参数；发送后执行。保留原始 slash 文本，不替换成一段看起来相似的提示词 |
| `/code-review` | 交给原生 CLI；AI 审查集中在命令入口，代码变更面板不再重复放“审查代码”。默认不加 `--fix`、`--comment` 或 `ultra` |
| `/init`、`/simplify`、`/security-review` 等 | 以当前 CLI 报告的可用列表为准；项目/用户同名覆盖保留其真实说明，不套用内置说明 |
| `/model`、`/effort`、`/permissions` | GUI 会话控制，打开当前聊天的对应选择器，明确标记为“会话控制” |
| `/config`、`/mcp`、`/tasks` | GUI 适配：打开设置、MCP 管理；tasks 定位并展开聊天中的代理/后台任务卡片，不另开任务页，不发模型请求 |
| `/cost`、`/usage`、`/context` | 同一用量详情。上下文仅采用读取到的 CLI 报告，缓存与 Token 采用实际返回计数 |
| `/clear` | 创建空的新会话，原聊天保留；接入、模型、思考、权限、运行选项一次性继承，不先切换到默认模型再补写 |
| `/help` | 打开当前命令与技能列表；GUI 快捷键说明从应用帮助打开 |
| `Ctrl+K` | 独立应用操作搜索，含连接、项目、差异、工作区、归档、诊断等；保留输入草稿 |
| `@` | 搜索并附加项目文件路径引用，模型按需读取 |
| `#规则内容` | GUI 快速记忆：展示保存位置，默认项目 CLAUDE.md，可切换个人全局 CLAUDE.md；Enter 或“保存记忆”直接追加，不调用模型。保留原内容并备份，后续 CLI 请求重新加载。可选“作为普通消息发送”，`##` 标题保持普通消息 |
| `Shift+Tab` | 输入框中循环标准权限 → 允许编辑 → 计划模式；运行期间不修改权限 |
| 选中文字右键 | 原生复制菜单 |
| 输入框右键 | 原生撤销、重做、剪切、复制、粘贴、全选；可用状态由 Chromium 编辑标志决定，粘贴会走正常 input/paste 事件更新 React 草稿 |

菜单宽度和高度受限，列表可滚动。快捷键上下移动时跟随选中项滚动；不显示一整块应用导航占据聊天。CLI 内部服务交接命令不列出；目录加载失败会保留可用的 GUI 控制与本地技能并显示错误。

模型选择器中的思考强度使用离散滑条，支持拖动、档位文字点击及键盘方向键/Home/End。保留模型配置的档位选择顺序，不按强度排序；关闭（仅模型声明支持时）放在最左，默认放在关闭与第一个启用档位之间。没有关闭时默认在最左，没有已知档位时仅保留默认。默认仍发送空 effort 以继承原有模型/服务设置，不等于关闭。调整强度保留菜单，选择模型沿用原来的关闭菜单行为。

每项命令均提供中文用途。原生命令使用维护的中文说明；项目/插件覆盖优先保留自己的中文说明。只有英文说明的未知技能显示中文的运行用途，不冒用同名内置命令说明。应用操作面板不再重复列技能。CLI 返回的独立 slash 建议（如输入框上方的小 `/init`）不展示；自然语言建议保留并加上“建议”标签。

原生历史中的完整 command-name / command-message / command-args 记录在显示、自动标题和重新生成时还原为 `/名称 参数`。不改写原始 JSONL，不处理正文、代码示例或助手输出中的相同标签。搜索命令时，名称完全匹配优先于描述匹配，避免输入 `/clear` 时误选用途说明中包含 clear 的 `/goal`。

右键编辑菜单接入主窗口及内置网页 WebContentsView，不替换已有的聊天/项目右键操作。通过原生编辑角色处理选区和撤销历史，不以读取整个聊天或直接覆盖输入值代替复制/粘贴。

子代理的启动工具、独立输出和关联 task ID 合并为一张默认折叠的高亮卡片。展开后才挂载子代理输出、思考和工具记录；主消息文本及普通工具列表不重复展示这些内容。关联后台任务的停止操作在卡片内。移除聊天顶部和应用操作里的重复任务页入口。迟到任务更新回写原消息，不在后续回复创建重复卡片。

历史同步不以 isMeta 消息或只有 tool_result 的消息选择主对话分支，迟到工具结果只回填对应工具。GUI 刚接收而 CLI 尚未写盘的消息用 pendingNative 标识临时保留，观察到其原生 UUID 后清除缓冲并继续仅使用 CLI 正文。部分 JSONL 快照不能覆盖已收到的完整回复。卡片展开仅修改本地展开状态，不改会话内容。

## 参考资料的边界

参考截图中的终端功能并不都是 `claude -p` 的输入协议。`#` 快速记忆由 GUI 直接写入原生说明文件实现，不把前缀透传给模型来冒充记忆保存。当前没有实现 `!` 直接 Shell 模式或双 Escape 编辑上一轮。当前官方文档将 Ctrl+R 定义为输入历史搜索，Ctrl+O 才是详细工具/转录视图，截图中的 Ctrl+R 说明不适用于当前版本。

2026-10-16 实测当前安装 CLI 的 `-p --input-format stream-json`：提交 `!echo BANG_NATIVE_OK > bang-proof.txt` 后，没有创建标记文件，上游收到的用户文本仍为原始 `!` 命令。使用隔离配置、禁用 Hooks/自动记忆、空 MCP 与本地模拟上游；模型没有发出工具调用。结论仅针对当前 GUI 所用协议：`!` 不会直接触发终端 Shell 模式，模型调用 Bash 是另一条路径。用户取消新增本地 Shell 通道，相关试做代码已撤回。

- [本地原生代码审查](https://code.claude.com/docs/en/code-review-local)：当前 `/code-review` 是内置技能，支持 `-p` 前台返回结果；与另行安装的同名 PR 插件、云端 Code Review 服务区分。
- [终端交互与快捷键](https://code.claude.com/docs/en/interactive-mode)：用来核实终端行为，GUI 仅列出已经实现的适配。
