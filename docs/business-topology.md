# 可视化业务拓扑 · 基础版

入口在聊天顶部的“业务拓扑”，也可以在 Ctrl+K 中搜索。默认打开铺满工作区的独立页面，顶部可切换半屏或展开；切换保留当前层级、选区和未保存批注。

## 按业务数据流阅读

画布以紧凑的处理步骤、具名输入输出端口和数据线展示业务。不同数据、成功/失败分支可以在同一对模块间分别连线；返回走独立回路，存储读写有不同线色。不再把流程超过三层的图强行折成卡片网格，打开时保持可读字号，可滚动平移，用右下角全景图定位；“查看全景”是主动操作，不会自动缩小到难以阅读。

子模块跨层连接会显示范围外的实际模块；入口、业务结果、父模块端口显示为边界。未映射的输入或输出显示“来源待核实 / 去向待核实”及虚线，它们是诊断标记，不会写进原图或冒充已确认的数据流。选中节点可突出其关联流程，点线继续使用原始节点/连线 ID 批注。完整端口名和数据说明可悬停查看。

## 自动深度的续跑与停止

自动深度使用程序计算的待展开队列。内部模块没有子模块、也没有通过实际代码核实的叶子停止记录，就仍属待探索；外部或存储黑盒也要说明停止依据。结构状态显示实际层数和未完成模块，不能只画一层就标全量完成。

自动探索的每次成功回复结束后，应用重新检查图及当前范围的数据流。还有可继续处理的模块或缺口时，在同一聊天继续发送内部探索指令；不增加可见用户消息，原生 CLI 历史保留真实输入，GUI 元数据只隐藏应用生成的续跑输入。最多连续 8 批，连续两轮没有进展则暂停并明确未完成，避免空转；用户可从待探索清单继续。停止操作仍能终止正在执行的批次。模型受限、代码缺失或图格式损坏时说明阻塞，不能自动算完成。

Skill 增加 `exploration:{state:"leaf"|"external"|"blocked",reason:"具体停止依据"}`。自动深度校验命令为 `node .claude/skills/workspace-topology/validate.cjs --explore-auto`，局部操作可加 `--modules=id1,id2`。这只能核对覆盖记录和数据流映射，实际业务语义及叶子理由仍需核对代码。

## 使用

1. 没有图的项目点击“生成首张拓扑”。应用安装项目 Skill `.claude/skills/workspace-topology/SKILL.md`（自动升级已知的内置旧版并保留 .previous 备份，自定义版本或校验器不覆盖），将分析任务加入聊天输入框。发送后，当前聊天使用的 CLI 与模型读取源码并写入 `.claude/workspace-topology.json`。已有草稿和附件保留。
2. 回复结束时自动重新读取图；AI 在外部终端更新后也可以点击刷新。每个模块都可双击进入，或点“展开内部拓扑”。没有子模块时会展示模块的用途、输入输出与“生成下一层拓扑”；已有子模块时可以通过顶部“继续细化此模块”请求进一步完善。请求绑定图版本与模块 ID，带上已有子树、祖先及边界连接，要求仅补充当前模块内部，保留父模块边界、已有 ID 和其他模块。发送后自动加载结果并保持在当前层级；新的子模块也可以继续双击、递归生成。通过面包屑或返回按钮回到上层。
3. 点选模块或数据流；Ctrl 多选，Shift 拖动框选。空白拖动平移，底栏缩放或适合宽度。选区详情与批注显示为非模态浮动窗口，可拖动标题栏或暂时收起，画布不因此缩小。Escape 先收起浮窗，再按一次关闭页面。顶部“批注”可查看当前图版本的批注记录。
4. 选择“询问 / 批注 / 修改要求 / 认可设计”。可以只保存到此图版本，也可以加入对话继续讨论。加入对话时自动切换半屏并显示精简选区标签；真正发送给 CLI 的上下文包含图版本、稳定 ID、选中对象、父模块、相邻节点与连接及代码引用。源文件始终需要重新核对。选区加入输入框后仍可移除，发送失败保留草稿。

“认可设计”只表示认可指定对象在指定图版本中的业务设计，不是通过测试或批准工具执行。图文件变化后旧选区会清除；旧批注不冒充新版本批注。已经加入输入框的旧选区在发送时重新校验版本，拒绝向不同版本的同名节点自动套用要求。

## 并发探索与重新生成

拓扑页顶部提供“并发探索”和“重新生成拓扑”；进入模块后提供“重新生成此模块”，节点批注浮窗也有“并发探索此节点 / 重新生成此节点”。Ctrl 多选或 Shift 框选多个模块后，浮窗提供“并发探索所选模块 / 重新生成所选模块”，顶部操作也采用当前选区。设置窗口可以选择整个项目、单个模块或勾选多个模块（最多 20 个），支持 1 层、2 层、N 层（1–100）及模型自行判断结束。整个项目的顶层模块算第 1 层；选中模块时，以最外层所选模块的直接子模块为第 1 层。父子模块同时选中会合并重叠范围，界面显示合并数量，后端保留原始选中 ID 和有效范围 ID，避免重复派发或误当全图重建。现有更深且有效的子树保留。混选连线时不能提交批量探索，需先取消连线选择。

并发探索任务要求主模型调用原生 Agent/Task，尽可能利用实际可用的并发能力，对独立模块分批派发只读探索，再继续覆盖下一层。子代理返回结构与代码证据，主模型统一去重、核对跨模块数据流并写图，避免多个代理同时覆盖图文件。实际调用数量、失败重派与停止条件由运行中的主模型和 CLI 决定，并不是应用自行启动固定数量的模型进程。代理输出沿用聊天中的独立子代理卡片。

优先采用同批前台并行调用；确需后台代理时必须显式等待结果并继续汇总。代理全部返回后，聊天继续显示“等待主模型核对并汇总写图”和阶段耗时，直到主任务的新结果完成。具体完成判定见 [子代理生命周期](agent-lifecycle.md)。

自动深度要求模型探索到可验证的业务叶子或明确边界，并列出停止依据。指定深度与图容量、上下文或运行限制冲突时，要求模型保留已验证结果，明确列出未完成范围；不能保证一次穷尽任意规模的代码库。此流程只分析并修改拓扑，不修改业务代码或发送生产请求。

“探索”侧重补齐缺口；“重新生成”要求依据当前代码重新推导所选范围，允许替换其中确已过时的结构。节点重新生成必须保留父节点与边界、祖先和兄弟模块；整图重新生成尽量复用语义未变的 ID。重新生成任务准备时，旧图按原始内容备份到应用数据目录 `topology/backups/<项目标识>/<图版本>.json`，界面提示实际路径。准备和发送均校验图版本，不会把旧设置悄悄应用到更新后的图。图文件由模型实际执行任务后写入；准备按钮只是把任务加入聊天草稿，发送后开始。

## 存储与边界

- 图在项目中，格式与分析流程由项目 Skill 约束；代码引用限于项目内部相对路径。不存在的文件、越界行号在界面提示待核实。
- 批注按项目与图版本保存于应用数据目录的 `topology/`，不会改动业务源码。旧版本批注保留存储，当前界面只展示当前图版本的批注。
- 拓扑选区作为聊天辅助元数据保留。CLI 原生历史仍是正文来源；图选区上下文保留在原生请求中，GUI 将正文精简展示为用户文字和可展开的选区详情。重新生成使用原始请求中的图快照。
- 这是静态结构图，不是自动执行追踪或真实性证明。只生成 / 重新分析只要求写图；拖动节点改线、从零编排业务、模拟执行、真实请求追踪、禁用模块与自动一致性检测尚未实现。
- 大型项目基础版最多 250 个节点、600 条边、1 MB；分层界面只展示当前层，但整个图文件仍一次读取。后续可拆成按模块懒加载的文件。
- 没有改变现有模型协议、图片路径传递、权限审批或浏览器选区机制；无需额外网页账号。

## 验证

`npm test`：图校验、稳定 ID、父子层级、同名模块区分、精确连接方向、路径范围、图版本冲突、批注持久化、代码引用与原生历史重放。

`npm run test:topology-ui`：独立临时项目通过测试 CLI 写图，验证生成流程、全页 / 半屏切换、浮窗拖动且不挤压画布、批注草稿保留、层级、点选 / 多选 / 框选、选区真正到达 CLI、精简正文、认可设计与重启保留、过期选区发送拒绝及真实项目首张图。不会调用付费上游。

`npm run test:topology-exploration-ui`：独立临时配置验证首次并发探索、1 / 2 / N / 自动深度、节点与全图重新生成、原生格式子代理事件卡片、图备份内容、模块范围及过期设置拦截。使用本地测试 CLI，不验证特定上游模型的真实探索质量或并发上限。


## 数据流完整性检查

拓扑不仅检查 ID 和层级，还逐项检查输入来源和输出去向。协议保持 `version:1`，新增 `flowVersion:1`：每条边通过 `sourceOutputs` / `targetInputs` 精确绑定两端 `outputs` / `inputs` 中的字符串；边有 `kind`（调用、数据、中介传递、存储读写、外部请求、返回）及真实代码引用。

入口、真实终点、外部黑盒和父子层级边界使用端口级 `boundaries` 声明方向、端口、类型、理由和代码引用。父子层级还需绑定同方向 `parentPort`。缺口写 `unresolved` 或 `uncertain`，不会因此算通过。`kind=terminal` 或 `external` 本身不会豁免检查。内部模块的存储写入或外部请求必须连向实际存储/外部节点。

生成、细化和并发合并后，Skill 要求运行 `node .claude/skills/workspace-topology/validate.cjs`。它与 GUI 共用解析和检查代码，输出 JSON 诊断；通过退出 0，否则退出 1。界面始终根据文件重新计算结果，不采用 AI 回复里的“已经完成”作为通过依据。旧图可以查看和局部批注，但未迁移的数据流映射会标为未通过完整性检查。局部设计认可不会清除全图缺口。

检查面板可展开定位缺少来源/去向的节点、未绑定端口的连线，并列出无入边/无出边的节点 ID。浮动详情展示边端口和边界依据。代码位置存在、映射闭合仍不证明业务语义正确或执行成功；真实终点理由和遗漏数据必须结合代码审阅。

回归：`npm run test:topology-flow-ui`；单测覆盖中介数据、缺失的存储/服务输出、真实终点、父子边界、旧图、证据缺失和安装升级。此轮不改写用户项目的业务图，也不打包 EXE。


## 双向设计与开发

“业务拓扑 → 设计与开发”集中提供三种方式：从需求设计/补全拓扑、按照拓扑开发、核对代码与拓扑。没有代码的项目可以从“从需求设计拓扑”开始。工作流支持整个项目、当前多选模块或单个模块，任务绑定原始图版本，加入输入框后由用户发送执行；过期版本拒绝发送。

设计阶段节点和边用 `status: planned`，节点带 `acceptance` 验收条件，尚无代码可保持 `refs: []`。数据流仍须闭合，不允许空图、漏端口或无验收条件的模块通过。只有真实代码落地后才回填 `implemented` 和实际位置。计划节点用虚线显示，浮动详情展示状态、验收条件与验证记录。实现一部分的父模块仍保留 planned。

默认检查仍要求全部实现证据；`node .claude/skills/workspace-topology/validate.cjs --design` 单独检查设计闭合，允许 pending-code 与实现测试失败，但不会忽略关系缺口或失效引用。两者不是测试结论。`verification: {status, summary, commands}` 保存模型报告的实际验证记录，显示为“报告通过/失败/尚未验证”，不是应用认证。失败的测试不妨碍重新按图修复代码。

“按照拓扑开发”会检查所选范围的数据契约和验收条件，带上子树与依赖边界；范围外尚未补全的独立模块不阻止局部实施。主模型按依赖顺序实现并更新拓扑，不得用空壳或假数据冒充实现。“核对代码与拓扑”只同步图，保留尚未实现的设计意图，偏离契约标为待核实。

项目有拓扑时，普通开发任务也会附加维护提示，要求先定位相关模块、开发后更新引用/状态/连接，以及重测或作废相关旧验证记录。这是对模型的工作规范，不是自动证明代码与设计等价；未同步或语义偏差仍需通过核对操作与实际测试发现。

回归：`npm run test:topology-workflow-ui` 从隔离的空项目开始，验证设计只写图、待实现与验收显示、局部实施上下文、模拟 CLI 生成真实示例代码并实际运行 Node 测试，再核对回图。测试未调用上游模型，因此不代表任意模型都能正确实现任意项目。
